# 06 — 驗證與除錯

## 1. 一鍵驗證

```bash
./scripts/demo.sh
```

它會：啟動 `swiftcache serve` → 用 Xcode 與 SwiftPM 各建置兩次（第二次把
DerivedData/`.build` 與本機 CAS 清光）→ 檢查第二次全部命中 → 印出 server 統計。

## 2. 不跑編譯器的最小驗證：`plugin_probe`

開發 server 時每次都跑 `xcodebuild` 太慢，而且很難分辨「沒命中」是 server 的錯還是
cache key 變了。`tools/plugin_probe.c` 直接 `dlopen` Apple 的 plugin，呼叫
`llcas_*` API，把整條路徑縮到 0.1 秒：

```bash
cc -O2 -o /tmp/plugin_probe tools/plugin_probe.c
PLUGIN=$(xcode-select -p)/usr/lib/libToolchainCASPlugin.dylib

# 寫入：建立 root→leaf 的物件圖並寫 action cache
/tmp/plugin_probe write "$PLUGIN" /tmp/cas-write /tmp/swiftcache/cache.sock

# 讀取：用全新的本機 CAS 目錄，只能從 server 拿
/tmp/plugin_probe read  "$PLUGIN" /tmp/cas-read  /tmp/swiftcache/cache.sock
```

成功時：

```
plugin version: 0.1
hash schema: luxon.blake2b
root  id: 00acf46bd4bdae45526962041ccaa14d25bfc614…
root data: 23 bytes, prefix 'swiftcache root payload'
root refs: 1
leaf data: 4194304 bytes, prefix 'swiftcache leaf payload'
OK: round-tripped through the remote cache
```

第五個參數可以指定 leaf 的大小（bytes），用來強制走 `CASDBService.Save`/`Load`
而不是被內嵌進 KV value：

```bash
/tmp/plugin_probe write "$PLUGIN" /tmp/cas-write /tmp/swiftcache/cache.sock 4194304
```

## 4. 常見問題

### 建置成功，但 server 完全沒有流量

依序檢查：

1. `COMPILATION_CACHE_ENABLE_PLUGIN=YES` 有沒有設。沒設就是用內建 CAS，
   `REMOTE_SERVICE_PATH` 會被忽略（會有 warning，但很容易被洗掉）。
2. socket 路徑是否正確、server 是否先啟動。plugin 連不上時會安靜地退化成純本機快取。
3. 本機 CAS 是不是已經命中了。先 `rm -rf $COMPILATION_CACHE_CAS_PATH`。
4. `COMPILATION_CACHE_REMOTE_SUPPORTED_LANGUAGES` 是否把你的語言排除掉了。

### `-cache-compile-job cannot be used without explicit module build`

命令列少了 `-explicit-module-build`。swift-driver 只警告不報錯，快取會被靜默關閉。

### `stat cache file '….sdkstatcache' not found`

用了 SwiftPM 的預設 `swiftbuild` 引擎 + `-Xswiftc` 偷渡快取旗標。改用
`--build-system native`，原因見 [04-SwiftPM 設定](04-SwiftPM-設定.md#3-為什麼現在不能用預設的-swiftbuild-引擎)。

### `makeRemoteValue: data part is large with non-zero references`

plugin 拒絕上傳「資料很大且同時帶 refs」的節點。真實編譯輸出不會長這樣，只有手工
造測試資料時會踩到；把大 payload 放在沒有 refs 的葉節點即可。

### 第二次建置還是 miss，key 不一樣

cache key 含絕對路徑與工具鏈版本。跨機器或跨目錄要命中必須：

* Xcode 版本與 SDK 版本一致；
* 開啟 prefix mapping（`SWIFT_ENABLE_PREFIX_MAPPING`、`CLANG_ENABLE_PREFIX_MAPPING`、
  `SWIFT_ENABLE_PROJECT_PREFIX_MAPPING`、`CLANG_ENABLE_PROJECT_PREFIX_MAPPING`），
  讓 SDK / Xcode / 專案路徑被換成 `/^sdk`、`/^xcode`、`/^src` 等符號前綴。

### 怎麼看 server 到底存了什麼

```bash
# action cache 項目就是序列化的 kv.Value
xxd /tmp/swiftcache-store/kv/de/deadbeef…1c | head

# CAS 物件：前 6 bytes 是 magic "SWCAS\x01"
xxd /tmp/swiftcache-store/objects/1e/1e9e5114… | head
```

## 5. 自己動手挖協定

這些指令可以重現本文所有關於 plugin 行為的結論：

```bash
PLUGIN=$(xcode-select -p)/usr/lib/libToolchainCASPlugin.dylib

# 它連哪些 gRPC 方法
strings -a "$PLUGIN" | grep '^/compilation_cache_service'

# 它支援哪些 plugin 選項
strings -a "$PLUGIN" | grep -E 'remote-service-path|on-disk-root-path'

# 它匯出哪些 llcas_* 進入點
nm -gU "$PLUGIN" | grep ' T _llcas_'

# Xcode 認得哪些 COMPILATION_CACHE_* build settings
strings -a "$(xcode-select -p)/../SharedFrameworks/SwiftBuild.framework/Versions/A/PlugIns/SWBBuildService.bundle/Contents/Frameworks/SWBCore.framework/Versions/A/SWBCore" \
  | grep -oE 'COMPILATION_CACHE[A-Z_]*' | sort -u
```
